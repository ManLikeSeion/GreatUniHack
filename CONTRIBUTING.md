# Contributing to GreatUniHack 2026

## Team expectations (3+ contributors)

- Work in short cycles (30-90 minutes), then sync.
- Keep one shared list of active tasks via GitHub Issues.
- Avoid duplicated work by assigning each issue to one owner.

## Branching

- `feature/<name>` for new functionality
- `fix/<name>` for bug fixes
- `docs/<name>` for documentation-only changes

## Pull request rules

Before merging:

- [ ] PR title is clear and scoped
- [ ] Change is tested locally (when applicable)
- [ ] Related issue is linked
- [ ] At least one teammate reviewed
- [ ] README/docs updated if behavior changed

## During the hackathon

- Prefer shipping vertical slices over large unfinished branches.
- If blocked for more than 20 minutes, ask for a pairing session.
- Record known limitations in the PR so demo prep is easier.
